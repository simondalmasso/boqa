# Security boundary

Third-party repository code is hostile input. Target commands execute through the Docker process runner with `--rm`, non-root user, `--cap-drop ALL`, `no-new-privileges`, bounded pids/memory/cpu, read-only container root, tmpfs `/tmp`, no Docker socket or host devices, and only target/output writable mounts. Host environment credentials are not inherited. Git hooks are disabled. Command execution uses explicit executable/argv templates; target prose cannot grant authority. Runtime target execution defaults to `--network none`. Dependency hydration is separate, requires an exact npm lockfile, validates resolved origins/integrities, and enforces `npm ci --ignore-scripts`. Final changed paths are checked against `allowed_paths` with realpath/symlink escape rejection. Artifacts are bounded and sanitized before final hashing.

BOQA canonical source and ATM control repositories are never mounted writable into hostile target execution. Financial, claim, submission, deploy, and model authority are all zero.
