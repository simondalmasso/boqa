# BOQA Turbo UI Brief

Lane: lab/boqa-turbo-ui-v1

## Product intent

Build a standalone product-shell prototype for BOQA using the information density and interaction grammar of Borland Turbo Pascal / MS-DOS without pretending to be a literal terminal. The visual system must serve evidence clarity first.

Promise: **BOQA — Browser QA with proof**
Primary line: **Turn browser failures into verified regressions.**

## Truth contract

- Every visible opportunity, evidence item, verdict, gate and outcome is an explicit synthetic fixture.
- No live radar, target scan, bid, submit, wallet, payout, market registration, Cloudflare binding or runtime action is connected.
- Actions that cannot operate are labeled PREVIEW, READ ONLY, NOT CONNECTED or N/D.
- AMBIGUOUS is never styled as success.
- System health is N/D when not observed.
- Human Gate blocks only its dependent operation; unrelated work remains available.

## Visual direction

North star: Borland-blue workspace, gray chrome, cyan cues, green selection, black shadows/status bars, compact monospace hierarchy, pixel-crisp geometry and functional motion only.

Current live BOQA extraction was used only as context: dark base; implementation-inferred green #10b981, accent #f43f5e, background #09090b, Inter + JetBrains Mono. The prototype intentionally replaces that system with the Turbo direction while preserving semantic clarity.

## Mascot

Official UI character: BOQA. Source is the supplied 1024x1024 PNG. Adobe background removal produced a transparent cutout staged at prototype/turbo-ui/assets/boqa-mascot.png.

Use: Command Center, Help/About, Human Gate waiting state. Never use as proof, trust badge, security verdict or fake achievement.

## Required viewports

1440x900; 1366x768; 390x844; 360x800.

## Constraints

No root dependency, framework, backend import, runtime import, production endpoint, Cloudflare binding, merge or deploy.
