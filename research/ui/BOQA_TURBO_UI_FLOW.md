# BOQA Turbo UI Flow

## Primary flow

Command Center / Radar → Opportunity Inspector → Policy + Scope → Decision → Human Gate when required → Evidence → Submission Status (NOT CONNECTED in prototype) → Payout Status (N/D / NOT CONNECTED in prototype).

Secondary: Skills, Outcome Memory, System, Help.

## Keyboard map

F1 Help; F2 Radar; F3 Opportunity / Radar inspector; F4 Human Gates; F5 Refresh preview only; F6 Evidence; F7 Memory; F8 Verify / Evidence; F9 System; F10 menu focus; Esc Command Center.

## Human Gate model

The gate surface shows reason, risk, evidence references, proposed action, approve/deny PREVIEW controls, and explicit text that unrelated operations continue. No gate decision leaves the browser or mutates runtime state.

## Mobile

Desktop multi-pane views become stacked panels. The full desktop menu is replaced by a compact command strip while product semantics and labels remain unchanged.
